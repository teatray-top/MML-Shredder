# Python·Rust 비교 결과

이전 비교는 실제 붙여넣기 경로를 빠뜨렸습니다. 사용자는 Python 출력은 마비노기 게임에서 맞게 들리지만 Rust 출력은 맞지 않는다고 보고했습니다. 0.2.5의 36개 `.mmi` 파일이 같다는 결과만으로 복사·텍스트 출력과 게임 재생까지 같다고 판단할 수 없습니다.

## 0.2.14 검사: Roles 주선율의 배정 우선순위

Roles 배치에서 주선율로 선택된 음이 트랙 2로 밀리는 오류를 확인했습니다. 0.2.12의 연속성 처리는 원본 파트가 같으면 이전 출력 파트를 우선했지만, 하나의 원본 파트 안에서도 반주가 주선율로 바뀔 수 있습니다. 원본 파트의 이동 횟수가 적다는 사실만으로 주선율의 역할이 유지됐다고 판단할 수 없었습니다.

0.2.14는 Roles가 추출한 첫 번째 주선율을 **트랙 1·파트 1**에 우선 배정합니다. 반주를 배치할 때 뒤에 시작할 주선율과 겹치는지도 확인합니다. 보조선율과 반주는 기존 원본 성부의 연속성을 계속 사용하며, 주선율 추출 점수와 음표 축소·길이·템포 계산은 변경하지 않습니다. 최고음을 무조건 주선율로 취급하는 변경은 아닙니다.

2026-09-09, 실제 원본 `Op. 39 No. 11 Ouverture.mmi`를 **배포 CLI 0.2.13과 0.2.14**로 편곡해 저장한 MMI를 대조했습니다. 설정은 `2트랙 × 3파트 / Roles / gain auto / lead-continuity 0.7`입니다. 보관된 Python의 동일한 역할 추출기로 주선율을 식별하고, 각 음의 `(시작, 끝, 음높이, 음량)`으로 실제 출력 위치를 고유하게 대조했습니다. 두 설정 모두 모호하거나 누락된 주선율 음은 없습니다.

| lead-pitch | 추출된 주선율 음 | 트랙 1·파트 1에 남은 음: 0.2.13 → 0.2.14 | 연속 주선율 음 사이의 출력 파트 변경 |
|---|---:|---:|---:|
| 0.6 | 3,731 | 1,445 → 3,731 | 823 → 0 |
| 2.0 | 3,878 | 1,962 → 3,878 | 691 → 0 |

문제 구간의 원본 트랙 1·파트 2에서 **5112~5376틱의 11음**은 두 설정 모두 트랙 1·파트 1로 돌아왔습니다. 원본 트랙 1·파트 3의 **5568~5760틱의 8음**도 `lead-pitch 0.6`에서는 주선율이므로 같은 위치로 돌아왔습니다. `2.0`에서는 이 8음이 보조선율로 선택되므로 기존 트랙 2·파트 3 배치를 유지합니다. 따라서 이 두 구간은 각각의 역할 선택을 기준으로 검사합니다.

두 설정 모두 저장된 **14,047음 전체의 시작·끝·음높이·음량과 중복 수가 0.2.13과 정확히 같습니다**. 추가·삭제·변경된 음표는 0개이며 트랙별 템포, 정규화한 전체 템포, 헤더·박자표와 트랙·파트 수도 같습니다. 별도로 `1/2트랙 × Voices/Hands/Roles × gain none/auto`의 12가지 배포본 출력은 0.2.12와 음표·템포·유지/길이 축소/삭제 수가 모두 일치했습니다. 그중 **Hands·Voices 8개 MMI는 파일 바이트까지 동일**했습니다. 모두 최종 `dist/0.2.14/mmlfold.exe`로 저장한 결과입니다.

## 0.2.12 기록: 피아노롤 조작과 성부 연속성

화면의 외부 프로그램 내보내기 안내를 제거합니다. 재생 위치 **따라가기**는 기본으로 켜 두고 새 원본이나 새 결과를 만들 때 다시 켭니다. **Shift+마우스 휠**은 가로 이동, **Ctrl+마우스 휠**은 표시 범위 확대·축소에 사용합니다. 아래 버전 기록의 내보내기 안내는 당시 화면에 대한 설명입니다.

성부 배정은 같은 원본 파트의 바로 이웃한 음을 추적하고, 1박(96틱) 이하의 쉼표를 사이에 둔 음도 이전 출력 파트에 우선 배정합니다. 같은 시각에 시작하는 음들은 이어지는 성부부터 자리를 잡고, 새 성부를 넣을 때는 짧은 쉼표 뒤에 돌아올 다른 성부의 다음 음까지 확인합니다. 사용할 수 있는 다른 파트가 있으면 그 자리를 막는 배정을 피합니다. 성부 축소 과정의 음표 선택은 그대로 두고 출력 파트 배정을 변경한 것입니다.

새 배정으로 정확한 MMI 인코딩에 실패하는 입력은 기존 배정으로 다시 시도합니다. 이 예외 처리는 원래 음표 시각을 유지하면서 표현 가능한 출력을 만들기 위한 것입니다.

연속성 측정은 원본의 동일 `(트랙, 파트)`에서 바로 이웃한 두 음이 모두 결과에 남고, 시작 시각·음높이로 출처를 고유하게 식별할 수 있는 경우만 비교합니다. 삭제된 음을 건너뛰어 연결하지 않으며, 출처가 모호한 유니즌은 제외합니다. 이 지표는 원본 성부의 연속성을 측정하며 모든 원본 파트를 청각적 주선율로 판별했다는 뜻은 아닙니다. 별도로 실제 저장된 MMI를 읽어 수정 전후의 음표 시작·끝·음높이·음량과 템포를 비교합니다.

2026-09-09, 실제 원본 `Op. 39 No. 11 Ouverture.mmi`를 **배포 CLI 0.2.11과 0.2.12**로 각각 편곡해 저장한 MMI를 대조했습니다. 연속성 비교 설정은 `2트랙 × 3파트 / gain auto`이며, 아래 값은 비교 가능한 음 쌍에서 출력 파트가 바뀐 횟수입니다.

| 원본 두 음 사이의 쉼표 | 비교한 음 쌍 | Hands: 0.2.11 → 0.2.12 | Roles: 0.2.11 → 0.2.12 |
|---|---:|---:|---:|
| 없음 | 9,077 | 1,041 → 0 | 1,406 → 0 |
| 48틱 이하 | 12,798 | 2,253 → 17 | 2,768 → 20 |
| 96틱 이하 | 12,948 | 2,333 → 19 | 2,847 → 23 |

1박 이하 쉼표를 포함한 파트 이동률은 Hands **18.02% → 0.15%**, Roles **21.99% → 0.18%**입니다. A→B→A로 연속해서 되돌아가는 배정은 각각 650건·736건에서 두 배치 모두 1건으로 줄었습니다. 두 배치의 저장된 14,047음은 0.2.11 결과와 시작·끝·음높이·음량이 모두 같고, 트랙별 템포와 헤더·박자표도 같습니다.

같은 실제 원본에 `1/2트랙 × Voices/Hands/Roles × gain none/auto`의 **12가지 설정**도 별도로 실행했습니다. 모든 설정에서 저장된 음표의 `(시작, 끝, 음높이, 음량)` 집합과 중복 수, 정규화한 템포, 유지·길이 축소·삭제 수가 0.2.11 결과와 정확히 일치했습니다. 출력 트랙·파트 수와 헤더·박자표도 같았습니다. 슬롯 배정이 달라지는 만큼 `spill` 통계는 이 동등성 검사에서 제외했습니다.

성부 배정이 바뀌므로 0.2.12의 파트별 MML과 전체 `.mmi`는 이전 Python 편곡과 달라집니다. `scripts/check_parity.py`의 엄격한 문자열 비교 기준은 유지하며, 이 검사에 나온 차이를 없애기 위해 허용 기준을 낮추지 않습니다. 아래 과거 버전의 파일 완전 일치 결과는 현재 성부 배정 결과에 대한 주장이 아닙니다.

## 0.2.11 기록: 미리듣기를 모노로 변경

사용자 요청에 따라 미리듣기의 모든 음을 하나의 모노 신호로 섞습니다. MMI 트랙의 팬과 YDP 음원의 건반별 팬은 미리듣기에 적용하지 않습니다. 스테레오 출력 장치에는 좌우가 완전히 같은 신호를 보냅니다. 저장하는 `.mmi`의 팬 메타데이터는 변경하지 않으며, 이 변경은 편곡·분할 파일 출력에 영향을 주지 않습니다.

## 0.2.10 기록: 보고서 제거와 피아노 음원 교체

GUI의 보고서 탭과 저장 결과에 자동으로 붙이던 보고서 파일을 제거합니다. 기본 편곡 저장은 전체 `.mmi`만 만들며, **트랙별 파일도 만들기**는 기본으로 꺼 둡니다. 사용자가 이 옵션을 켜면 트랙별 `.mmi`를 추가합니다. 분할 저장도 장별 `.mmi`만 생성합니다. 명시적으로 요청하는 CLI `--report`는 개발 진단용으로 남깁니다.

게임용 악보는 계속 **MMI 저장 → MabiIcco에서 열기 → MabiIcco에서 내보내기** 경로를 사용합니다. 직접 복사와 게임용 MML 텍스트 파일을 다시 추가하지 않습니다. 아래 0.2.9의 보고서 출력 설명은 당시 버전의 기록입니다.

사용자는 0.2.9의 Kawai 업라이트 음원에서 잡음·울림·먹먹한 저음을 지적했습니다. 0.2.10에서는 **YDP Grand Piano** 2016-08-04 원본 SF2로 교체합니다. Yamaha Disklavier Pro의 녹음은 Dr. Mikhail Krishtal과 Zenph Studios 팀이 제작했고, FreePats의 Roberto가 SoundFont로 구성했습니다. 라이선스는 CC BY 3.0이며 원본 설명과 라이선스를 배포에 포함합니다. [FreePats 공식 출처](https://freepats.zenvoid.org/Piano/acoustic-grand-piano.html)

SF2는 118,398,836바이트(112.91MiB), SHA-256은 `8757076aecf80abdad1e8f8f6168370399b06f94481796986e6e75ceca09ad21`입니다. 공식 압축 파일의 약 36MiB 표시는 설치된 음원 크기가 아닙니다. 실행 파일에는 전체 원본 SF2를 포함합니다. 이 음원 교체는 미리듣기에만 적용하며 게임용 `.mmi`의 템포·음표 길이는 변경하지 않습니다.

샘플러는 프리셋의 다섯 강도 구간과 음높이에 맞는 녹음을 선택하고, SF2의 음량 변화를 반영합니다. 샘플 사이 값은 3차 보간하며, 121개 녹음의 자연스러운 감쇠를 재생하고 끝난 샘플을 반복하지 않습니다. 0.2.10 당시에는 건반별 좌우 배치와 트랙 팬도 반영했으나, 0.2.11에서는 위와 같이 모노로 변경했습니다. 재생 시간은 기존 오디오 샘플 기준 시계를 사용하며, 위치 이동 시에는 각 음의 경과 시간에 해당하는 샘플 위치와 감쇠 상태를 즉시 복원합니다. 관련 구현은 [src/piano.rs](../src/piano.rs)와 [src/synth.rs](../src/synth.rs)에 있습니다.

## 0.2.9 기록: MMI 파일 저장으로 통일하고 피아노 음원 교체

사용자는 `.mmi` 파일을 저장하고 **MabiIcco에서 내보낸 결과는 소리가 정상**이라고 확인했습니다. 이에 따라 0.2.9에서는 게임에 바로 붙여넣는 기능을 제거하고 **MMI 저장 → MabiIcco에서 열기 → MabiIcco에서 내보내기**로 사용 경로를 통일합니다. 이는 사용자가 확인한 파일 경로를 채택한 변경이며, 이전 직접 복사 결과가 다르게 들린 내부 원인을 확정한 것은 아닙니다.

GUI의 파트별·트랙별·전체 트랙 복사 버튼과 원시 MML 복사 화면을 제거했습니다. **출력 파일** 탭에는 저장할 파일 목록과 **MMI 저장…** 버튼을 제공합니다. GUI·CLI 공통 출력은 `.mmi`와 보고서만 남기고, 편곡의 `*_game.txt`와 분할의 장별 MML `.txt`는 생성하지 않습니다. 편곡·분할 결과는 파일로 저장한 뒤 사용합니다.

사용자가 선택한 경량 내장 피아노 방식으로 미리듣기 음원을 교체합니다. 실제 Kawai 업라이트 피아노 녹음인 **Upright Piano KW (small)**의 2019-07-03 SF2 파일 9,456,310바이트(약 9MiB)를 실행 파일에 포함합니다. FreePats의 CC0 음원이며 별도 VST나 음원 설치는 필요하지 않습니다. [FreePats 음원 안내](https://freepats.zenvoid.org/Piano/acoustic-grand-piano.html)

당시 구현은 [src/piano.rs](../src/piano.rs)에서 `rustysynth 1.3.6`으로 SF2 데이터를 읽고, 자체 음표별 렌더러로 녹음된 샘플을 재생했습니다. 기존 `Timeline`의 샘플 기준 재생 시간, 위치 이동과 팬 처리를 유지했습니다. 음원 교체는 미리듣기에만 적용했으며 저장하는 `.mmi`의 템포와 음표 길이 계산은 변경하지 않았습니다.

아래는 **0.2.8 및 그 이전 버전의 검사 기록**입니다. 직접 복사·MML 텍스트 출력과 관련된 버튼·파일은 0.2.9의 사용법이나 현재 제공 기능을 설명하지 않습니다. 내부 문자열 검사, 당시 GUI 클립보드 확인과 사용자가 게임에서 확인한 소리는 각각의 확인 범위를 구분해 기록합니다.

## 0.2.8 검사 기록: 재생 환경 확인과 복사 대상

사용자는 **마비노기 모바일의 PC 클라이언트**에서 재생한다고 명확히 했습니다. 기존 Python 출력의 `scrolls_solo` 텍스트를 직접 복사하면 정상이며, 0.2.7 출력에서는 여전히 타이밍이 맞지 않는다고 보고했습니다. 따라서 0.2.7의 문자열 대조 결과를 사용자 증상이 해결됐다는 의미로 해석하지 않습니다. 원래 마비노기의 PC 게임을 전제로 한 과거 템포 처리 설명도 이 재생 환경에 그대로 적용할 수 없습니다.

| 파트·트랙·헤더에 분산된 템포 | 5개 | 1개 | 5개 |
| 헤더에만 있는 템포 | 2개 | 0개 | 2개 |

Python은 마지막 템포 포함 파트와 첫 템포 포함 트랙에 제한된 값을 사용합니다. Rust는 파트·트랙·헤더를 합쳐 출력하므로 두 구현은 이 입력에서 다릅니다. 이 검사는 MML 명령 비교이며, 어떤 출력이 게임에서 사용자가 기대한 소리를 내는지 확인한 것은 아닙니다. 0.2.6의 복사 경로 변경만으로 이 파싱 차이까지 없어지는 것은 아닙니다.

## 0.2.5 검사 재실행과 범위

```powershell
python scripts/check_parity.py --binary dist/0.2.5/mmlfold.exe --source Op39No11_full_6part.mmi
python scripts/check_parity.py --binary dist/0.2.5/mmlfold.exe --source Op39No11_solo_3part.mmi
python scripts/check_parity.py --binary dist/0.2.5/mmlfold.exe --source Op39No11_second_3part.mmi
cargo test
```

`check_parity.py`의 `rust_split_integrity`는 Rust 분할 결과의 무결성 검사이며 Python 분할기와의 대조를 뜻하지 않습니다. 실제 분할기 대조는 위 별도 보고서에 기록했습니다. Rust 회귀 검사 72개 통과, 수동 오디오 성능 측정 1개 제외, Clippy와 포맷 검사도 통과했습니다. 마비노기 게임 안에서의 합주 재생은 이번 검사에 포함되지 않았습니다.
